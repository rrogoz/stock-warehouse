# SW-15: Fix the agent workflow gaps found in the dry run

Two pages at most. File `docs/specs/SW-15.md`. Frozen after the change merges; lasting facts move into docs or config first.

- **Story:** https://rrogoz-sw.atlassian.net/browse/SW-15

## Goal

The M0 dry run (SW-14) needed hand moves in Jira, hid the tool calls an agent was refused, and used a refinement model too light for a demo goal. Make CI own the In review and Awaiting release moves ([ADR-010](../adr/0010-tracker-and-story-workflow.md) table), make refused tool calls visible after every run, and refine on sonnet ([ADR-011](../adr/0011-agent-orchestration.md)). M0 deliverable 4 in the [overview](../overview.md).

## Design

**1. CI moves the story (AC 1).** `story-status.yml` runs on `pull_request_target`, types `opened`, `reopened`, `closed`, so it runs the workflow from main with the `JIRA_*` settings, as the review workflow does ([ADR-011](../adr/0011-agent-orchestration.md), review cannot be tampered with). It checks out main only, never the pull request head; title, event and merged flag reach the script through `env`, never interpolated (as in `change.yml`). Permissions: `contents: read`.

`story_status.py` holds a pure function `target(action, merged, title) -> (key, status) | None` and a `main` that applies it with role `ci`:

| Event | Title | Move |
| --- | --- | --- |
| `opened`, `reopened` | change pull request with `[SW-NNN]` | to In review |
| `closed`, merged | change pull request with `[SW-NNN]` | to Awaiting release |
| `closed`, not merged | any | none |
| any | starts with `docs(specs)`, or has no story key | none, with a notice in the log |

The key is read with the same `\[(SW-\d+)\]\s*$` pattern as `github_api.py` (import it, do not copy it). Before moving, the script reads the story's status; if it is already the target, it logs that and exits 0, so a reopen or a rerun is not an error. Any other Jira failure fails the job, visibly in Actions. The job is **not** a required check: Jira status is never a gate ([ADR-010](../adr/0010-tracker-and-story-workflow.md)); the daily consistency check catches drift. Awaiting release on merge is the state ADR-010 names; the release candidate step joins it with the M1 PROD story.

**2. The implement agent stops moving Jira (AC 2).** In `jira.py` `MOVES["implement"]` becomes empty, so the role can read and comment but not move (least privilege, ADR-011); `fix` keeps using that role. `agent-implement.yml` task text ends "... open one pull request on the template; CI moves the story to In review." The role skill's Output line already says this; no change unless the implementation finds a mismatch.

**3. Refused tool calls are visible (AC 3).** In `agent.yml` and `agent-review.yml` the action step gets `id: claude`, and a following step with `if: always()` runs `python3 .github/scripts/agent_report.py "$EXECUTION_FILE"` with `EXECUTION_FILE: ${{ steps.claude.outputs.execution_file }}`. The script reads the final `result` message's `permission_denials` (tool name and input) from the action's execution log and writes a table to the run log and `$GITHUB_STEP_SUMMARY`: "No refused tool calls", or one row per denial, input cut to 300 characters. A missing or unreadable file gives a notice and exit 0, so the report never hides the agent's own result.

Secrets: the full execution log is **not** uploaded as an artifact, because the repository is public and artifacts are not masked. The report step has no secret in its `env`, and GitHub masks registered secrets in logs and summaries. The implementation confirms `execution_file` and `permission_denials` on the pinned `claude-code-action@v1`; if they differ, it stops and says so on the pull request.

**4. Refinement on sonnet (AC 4).** `agent-refine.yml` model options become `[sonnet, opus]`, default `sonnet`, so "next model up" (runbook step 2) still has a choice. The runbook table row says sonnet. ADR-011's models line becomes: "strongest for planning, spec and review; middle for refinement, because verdict accuracy is a demo goal (Rafal, 2026-11-10), and for implementation, moving up when a story fails twice; lighter for small fixes." Editing an accepted ADR needs Rafal's code-owner approval (gate 2, [ADR README](../adr/README.md)); this spec asks for it.

Names follow the [naming standard](../standards/naming.md); the change follows the [change conventions](../standards/change-conventions.md).

## Tests

| Acceptance criterion | Check |
| --- | --- |
| 1. CI moves to In review on open, Awaiting release on merge; spec pull requests do not move | `test_story_status_target`, parametrized over the table above, including `docs(specs): add spec [SW-15]`, a closed unmerged pull request and a title without a key. `test_story_status_skips_current_state` and `test_story_status_moves` use the fake Jira already in the test module: no transition is posted when the status is the target; one `ci` transition otherwise |
| 2. Implement agent no longer moves Jira; task and skill match | `test_jira_move_allowed` asserts `not allowed("implement", "In review")` and `allowed("ci", "In review")`; the existing implement move test changes to role `ci`. `test_implement_task_leaves_move_to_ci` reads `agent-implement.yml` and asserts the task has no `move` instruction and names CI. Review checks the skill wording |
| 3. Refused tool calls visible after a run, no secrets | `test_agent_report` on synthetic execution files: two denials give two rows with tool name and cut input; none gives "No refused tool calls"; a missing file gives exit 0. Review checks that both workflows run the step with `if: always()`, no secret in its `env` and no artifact upload. The first agent run after merge is the live check |
| 4. Refine default model is sonnet in workflow and runbook; ADR-011 line updated | `test_refine_default_model` loads `agent-refine.yml` with `yaml.safe_load` and asserts default `sonnet`, and asserts the runbook's `agent-refine` row says `sonnet`. Review checks the ADR-011 line |
| 5. Docs updated | Review against Docs to update; `check_docs.py` passes |

All checks in the [README](../../README.md#run-locally) pass. Testing rules: [testing standard](../standards/testing.md); the tests use fakes, never the real Jira.
