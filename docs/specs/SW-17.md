# SW-17: Add trading calendar files for NBP and XWAR

Two pages at most. File `docs/specs/SW-17.md`. Frozen after the change merges; lasting facts move into docs or config first.

- **Story:** https://rrogoz-sw.atlassian.net/browse/SW-17

## Goal

Give the engine and quote status a reviewed list of sessions for `XWAR` (GPW) and `NBP` (table A publication days), 2002 to 2027, so a holiday is never mistaken for a missing fixing (D14). Calendars are reference files from a generator, never derived from prices ([ADR-005](../adr/0005-sources-and-ingestion.md)). M1 seed item 3 in the [overview](../overview.md).

## Scope

- **Generator:** new `src/engine/calendars.py`, run as `uv run python -m engine.calendars`.
- **Reference data:** new `reference/calendars/<calendar>_<year>.yaml`, 52 generated files (`xwar_2002.yaml` to `nbp_2027.yaml`).
- **Config schema:** new `config/schemas/trading_calendar.schema.json`.
- **Tests:** new `tests/unit/test_calendars.py` and fixture `tests/fixtures/calendars/known_days.yaml`.
- **Tooling:** dev dependencies `exchange-calendars` and `holidays` in `pyproject.toml`, `uv.lock` (generated); a mypy override for `exchange_calendars`, which has no type hints.
- **Docs:** [glossary](../glossary.md), new runbook `docs/runbooks/update-calendars.md`.

## Design

**One file per calendar and year,** so each new year is its own change Rafal approves ([ADR-005](../adr/0005-sources-and-ingestion.md); `reference/` is code-owned, [change conventions](../standards/change-conventions.md)). YAML validated by a JSON Schema ([ADR-009](../adr/0009-repository-and-standards.md)); names follow the [naming standard](../standards/naming.md). A file lists only the **closures**: weekdays without a session. Sessions are Monday to Friday of the year minus the closures. About 12 dated lines per year are easy to review; 250 sessions are not.

```yaml
# Trading calendar XWAR 2025: weekdays without a session (ADR-005).
# Generated by `python -m engine.calendars`; changes need Rafal's approval. Schema: config/schemas/trading_calendar.schema.json.
version: 1
calendar: XWAR
year: 2025
recorded_date: "2026-11-17"
closures:
  - date: "2025-01-01"
    name: New Year's Day
  - date: "2025-12-31"
    name: New Year's Eve
```

| Field | Meaning | Rule in the schema |
| --- | --- | --- |
| `version` | file format version | const `1` |
| `calendar` | `XWAR`: the exchange's MIC; `NBP`: the `nbp` source's publication days | enum `XWAR`, `NBP` |
| `year` | the calendar year the file covers | integer, 2002 or later |
| `recorded_date` | when this year's content was last written, so reference data is point in time ([ADR-004](../adr/0004-physical-data-model.md), data rules) | quoted ISO date, `format: date` |
| `closures[].date` | a weekday with no session | quoted ISO date, `format: date` |
| `closures[].name` | why: holiday name in English, or `Ad hoc closure` | non-empty string |

`additionalProperties: false` everywhere; each field has a `description`, its documentation home.

**Generator.** Pure functions plus a small `main`:

- `closures(calendar, year) -> list[Closure]`. `XWAR`: weekdays of the year that are not sessions of `exchange_calendars.get_calendar("XWAR")` (2002 is inside its range; 2018-01-02 and 2018-11-12 are among its ad hoc closures). `NBP`: weekdays that are Polish public holidays from `holidays.Poland(language="en_US")`, for example Epiphany only from 2011, 2018-11-12, Christmas Eve from 2025. Names: the Polish public holiday name if the date is one, else the `exchange_calendars` holiday name, else `Ad hoc closure`.
- The generator fails if `exchange_calendars` reports a weekend session or an early close in the year, because the format cannot express them; none exist for 2002 to 2027 today.
- `render(...) -> str` writes the header, keys in fixed order and dates ascending, so output is byte-stable.
- `main --from-year 2002 --to-year 2027 [--recorded-date YYYY-MM-DD]` (default today) writes `reference/calendars/`. A file whose closures are unchanged is left untouched, keeping its `recorded_date`; only changed or new years get the new date. `--check` writes nothing and exits 1 if any file would change.
- Pinned versions in `uv.lock` make the output reproducible; a library upgrade that changes a past year shows up as a failing test and a reviewed diff. Both libraries are dev dependencies: the pipeline image reads the files and never runs the generator. Nothing imports `engine.calendars` from the pipeline command.

**Rules a JSON Schema cannot express,** checked in the test: file name is `<calendar lower>_<year>.yaml`; closure dates lie in `year`, are weekdays, strictly ascending; duplicate YAML keys rejected (the unique-key loader pattern from `test_instrument_register.py`; the shared loader still waits for the first engine code that reads reference files).

**Known risk.** `NBP` assumes table A appears on every Polish working day. If real data later shows another non-publication day, it is a reviewed calendar change, never a fix in the data.

## Tests

| Acceptance criterion | Check |
| --- | --- |
| 1. Generator writes `XWAR` and `NBP` files for 2002 to 2027 | `test_files_cover_2002_to_2027`: exactly the 52 expected file names exist. `test_files_are_up_to_date`: `main --check` on the committed files exits 0 |
| 2. JSON Schema validates them; CI checks it | `test_real_calendars_are_valid` validates every file (Draft 2020-12, format checks on) plus the rules above, in pytest, which CI runs. `test_bad_calendar_fails`, parametrized over inline synthetic YAML: unknown calendar, unknown field, bad date, closure on a Saturday, closure outside the year, closures out of order, duplicate key, file name not matching. Each must raise |
| 3. Deterministic; known holidays and sessions match | `test_generator_is_deterministic`: two runs into `tmp_path` give identical bytes, and a rerun with another `--recorded-date` changes nothing. `test_known_days` reads the fixture: closures such as XWAR 2005-04-08, 2018-01-02, 2025-12-31 and NBP 2011-01-06, 2018-11-12, 2025-12-24; sessions such as XWAR and NBP 2010-01-06 (before Epiphany became a holiday), NBP 2024-12-24 and 2025-12-31 |
| 4. Docs describe the files and the yearly update | Review: glossary and runbook below; `check_docs.py` passes |

The fixture holds public holiday dates, not market data. All checks in the [README](../../README.md#run-locally) pass, including `check_no_real_data.py`. Testing rules: [testing standard](../standards/testing.md).
